# Forge Tap to Pay Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Finish native iPhone job payment and consented tap-to-save, with safe recovery and explicit recurring-card selection.

**Architecture:** A server-owned durable attempt bridges existing Stripe Connect billing to a native Capacitor Stripe Terminal plugin. Web UI creates and reconciles attempts, while native code exclusively collects payment details. Provider success is independently verified before updating Forge.

**Tech Stack:** Next.js 14, TypeScript, SQLite/libSQL, Stripe Connect, Capacitor 8, Swift/UIKit, Stripe Terminal iOS SDK via SPM.

**Spec:** docs/superpowers/specs/2026-09-16-tap-to-pay-design.md

## Global Constraints

- No live charges, deployment, push, entitlement submission or App Store upload.
- Hosted web + native iOS only; preserve existing manual card flows and unrelated files.
- Server derives tenant, connected account and payable amount; no client success trusted.
- Saving alone never activates a subscription or changes billing defaults/fallbacks.
- Persist no client secrets, complete card data or connection tokens; retain durable attempt IDs and consent evidence.
- Native plugin name `ForgeTerminal`; methods `getCapabilities`, `showEducation`, `collectPayment`, `collectSetup`, `cancel`, `reset`.
- New server routes use the exact TerminalAttemptView and StartTerminalAttempt contracts in the spec.
- Standard signed build remains usable without a newly approved entitlement; real Tap to Pay is gated until properly provisioned.
- User delegated spec review and authorized continued local implementation without another approval checkpoint.

Produces `ForgeTerminal` plugin methods from spec. collect arguments camelCase: `operationId`, `clientSecret`, `stripeAccount`, `locationId`, plus `saveCard` for payment. Returns `{ intentId }`; rejects with actionable codes `unsupported`, `busy`, `canceled`, `session_changed`, `payment_unknown`, or `terminal_error`.
